## 三、软件结构

### 关键宏

```c
#define UMAX        450      /* 输出限幅（占空比可调范围） */
#define PWM_DEAD    500      /* 死区：CCR 低于此值电机不转 */
#define PPR         1320     /* 输出轴一圈的脉冲数（×4 倍频后） */
```

### 速度换算

```c
float real_V = DELTA * 6000.0f / PPR;
```

- `DELTA` = 10 ms 内编码器脉冲数（`int16_t`，自动处理 16 位回绕）
- `6000 = 60 秒 ÷ 0.01 秒`：一分钟里包含的 10 ms 周期数
- 若控制周期改为 20 ms，系数改为 3000

**自校验证**：手转输出轴约 1 圈/秒 → `real_V` 应显示 60 左右。

### PID 结构

```c
typedef struct {
  float Kp, Ki, Kd;
  float e_last;       /* 上次误差（算 D） */
  float integral;     /* 误差累加（算 I） */
  float out_max;      /* 输出限幅 */
  float i_max;        /* 积分限幅，防积分饱和 */
} PID_USE;

float PID_Calculate(PID_USE *p, float tar, float now);
```

**为什么必须传指针**：`integral` 和 `e_last` 要跨调用保留，必须存在函数外的结构体里。

### 中断里的完整回路

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
  if (htim->Instance == TIM1)
  {
    int16_t now   = (int16_t)__HAL_TIM_GET_COUNTER(&htim2);
    int16_t DELTA = now - last;
    last = now;

    float real_V = DELTA * 6000.0f / PPR;

    float u = PID_Calculate(&PID, target, real_V);
    motor_set((int32_t)u);

    printf("%d,%d\n", (int)target, (int)real_V);   /* VOFA FireWater 双通道 */
  }
}
```

### 输出映射

```c
ccr = PWM_DEAD + |u|;          /* 500 ~ 950 */
u >= 0 → CH1 = ccr, CH2 = 0    /* 正转 */
u <  0 → CH1 = 0,   CH2 = ccr  /* 反转 */
```

**两个通道每次都要写**：`__HAL_TIM_SET_COMPARE` 是赋值，未被覆盖的通道会保持上一次的值，导致 H 桥两输入同时有效（刹车）。

## 五、踩过的坑（按发生顺序）

### 1. 启动代码放错位置 → HardFault

`HAL_TIM_Base_Start_IT` 等四行被误放进 `USER CODE BEGIN Init`，位置在 `SystemClock_Config()` 和 `MX_TIMx_Init()` **之前**。此时 `htim1.Instance` 还是 `NULL`，HAL 写 `NULL->CR1` → 程序一启动就死在 HardFault。

**修复**：移到 `USER CODE BEGIN 2`（所有 `MX_*_Init` 之后）。

### 2. 三个定时器参数全对错

```c
HAL_TIM_Base_Start(&htim1)                   /* 少 _IT，中断使能位没打开 */
HAL_TIM_Encoder_Start(&htim3, ...)           /* 应该是 htim2 */
HAL_TIM_PWM_Start(&htim2, ...)               /* 应该是 htim3 */
```

### 3. `#include <stdio.h>` 放进函数体内

放在 `USER CODE BEGIN Init`（位于 `main()` 内）会报 `invalid storage class for function '__sputc_r'`。必须放顶部的 `USER CODE BEGIN Includes`。

### 4. 中断回调必备三件套，缺一不可

| 条件 | 说明 |
| --- | --- |
| `HAL_TIM_Base_Start_IT()` | 带 `_IT`，否则只开计数器不开更新中断使能位 |
| NVIC 勾选 `TIM1 update interrupt` | CubeMX 里配置 |
| `stm32f1xx_it.c` 里有 `TIM1_UP_IRQHandler` | 高级定时器的更新中断入口带 `_UP` |

### 5. 编码器信号没接到 MCU

电机排线插进 TB6612 的 JST 座只是把编码器接到了**驱动板**，还要再从板子排针引 `E1A` / `E1B` 到 `PA0` / `PA1`。缺这一步时读数恒为 0。

### 6. 方向反了 → PID 变正反馈

现象：`target = 0` 时手拨一下电机，电机自己越转越快。

```c
error = target - real_V = 0 - (-40) = +40   /* 误差是正的 */
u = Kp × 40 = +32                            /* 反而加大输出 */
→ 更快 → 误差更大 → 输出更大 ...
```

**修复**：对调 `E1A` / `E1B`，或 `real_V` 取负。**修完必须开环验一次符号**，不能直接闭环。

### 7. 串口 0 字节 → TX / RX 忘了接

`USART1` 的 PA9/PA10 必须交叉接到 ST-Link VCP：`PA9 → VCP RX`、`PA10 → VCP TX`。接反或漏接时寄存器全对但收不到任何数据。

判据：SWD 读 `USART1->CR1 = 0x200C`（UE/TE/RE 全开）、`BRR = 625`（115200），且 `CFSR/HFSR = 0`（无 HardFault）——说明是物理链路问题，不是代码问题。

### 8. VOFA 收不到波形

| 原因 | 修法 |
| --- | --- |
| `printf` 缺 `\n` | FireWater 靠换行分帧，必须 `printf("%d,%d\n", ...)` |
| 用空格分隔 | 多通道必须用**逗号** |
| 数据格式选成 JustFloat | 文本输出要选 **FireWater** |

### 9. `motor_set` 用 `-u` 直接写寄存器

`CCR` 是 16 位无符号寄存器，写 `-500` 会变成 `65036 > ARR`，输出恒为 100% 占空比（想反转却全速正转）。**负数必须在换算时取绝对值，方向靠换通道。**

## 六、已解决的问题：供电带载塌陷

### 现象

```text
电池组空载          12.0 V
板子 VIN（电机转着）  2.2 V      ← 带载掉 10 V
OUT1/OUT2           1 V 多（70% 占空比下应约 8 V）
```

电机能转但极慢，`real_V` 只有个位数到十几，PID 完全无法在这个工作点上调。

### 已排除

- 代码：SWD 直读 `TIM3->CCR1 = 700`、`CR1 = 1`、`PA3 = 1`，固件输出正常
- 电池本身：空载 12 V 稳定，同款电池别人用没问题

### 根因（2026-11-15 17:00 确认）

**电源开关没打开。**

电池盒 / 底盘上的拨动开关处于 OFF，电池的 12 V 到不了输出端。VIN 上量到的 2.2 V 是逻辑侧串过来的漏电压，不是供电。

```text
电池组本身    12.0 V   ← 正常
开关           OFF     ← 输出被切断
板子 VIN       2.2 V   ← 浮空漏电
```

**排查弯路**：先后怀疑过电池内阻大、电池保护板限流（2~3 A）、DC 插头内径不匹配（5.5×2.1 vs 2.5）。都不是。

**正确顺序应该是**：先确认「开关之后的输出端」是否真有电压，再往下怀疑内阻和保护板。电池端 12 V、输出端 2 V 这个组合，本身就说明是**断开了**，不是「带载塌陷」。

### 解决

打开电源开关即可。之后：

```text
VIN        = 电池电压（7.4 V / 12 V，随电池型号）
OUT1/OUT2  = VIN × 占空比（70% 占空比、12 V 时约 8.4 V）
```

### 对后续工作的影响

- 之前按 12 V 记录的「死区 ≈ 500」「43 RPM @ 50% 占空比」数据**作废**，换电源后需重测
- 电压稳定前调出的 Kp/Ki 没有参考价值，**必须在正常电压下重新调**

### 三种信号的生成

```c
t += 0.01f;                                          /* 10 ms 一次 */

/* ① 阶跃 */
target = (t < 3) ? 0 : (t < 6) ? 200 : 300;

/* ② 固定频率 0.5 Hz、幅度 50、中心 200 */
target = 200 + 50 * sinf(6.2832f * 0.5f * t);

/* ③ 变频变幅 */
float f = 0.2f + 0.2f * t;                           /* 0.2 → 2 Hz */
float a = 30.0f + 50.0f * (t / 10.0f);               /* 30 → 80，需限幅 */
target = 200 + a * sinf(6.2832f * f * t);
```

> `sinf` 需要 `#include <math.h>`。
> **不要用 `printf("%f")`**：newlib-nano 默认不链接浮点打印，需要额外链接参数。转成 `(int)` 输出，或放大 10 倍当整数打印。

## 九、经验教训

1. **先怀疑硬件，再怀疑代码。** 本次 90% 的时间花在电源接触和接线问题上，代码本身一直是好的。
2. **查电源先查「有没有通」，再查「够不够」。** 电池端有电压、板端没电压，第一反应应该是开关/断线，而不是内阻和保护板。这次绕了最久的地方就在这。
3. **转得慢 ≠ 占空比不够。** 慢转有三种原因（占空比小 / 机械堵转 / 供电塌陷），只有第一种能靠加大占空比解决。后两种加大占空比会烧电机（之前已经烧过一个）。
4. **用寄存器验证，不要凭感觉。** SWD 直读 `CCR` / `CR1` / `IDR`，能一句话区分「固件没输出」和「硬件没响应」。
5. **闭环前必须开环验方向。** 方向反了就是正反馈，几秒钟内冲到满占空比。
6. **调 PID 前先保证工作点正常。** 电源不稳、死区未测、方向未验，这时候调的参数全是废的。
